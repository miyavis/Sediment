# Sediment 改进计划

> 目标：在保持本地优先与现有工作流的前提下，优先提升数据可靠性、Agent 写入安全、性能和移动端体验。计划依据仓库 README、`package.json`、CI 配置和现有测试目录整理。本文档是路线图，不代表下列阶段已经实现。

## 当前基线

- 当前版本：`0.8.7`
- 技术栈：Obsidian 插件（TypeScript/JavaScript），MCP stdio 桥接
- 已有命令：`npm run build`、`npm run test:unit`、`npm run test:mcp`、`npm test`
- 已有 CI：GitHub Actions 执行构建；需要确认并纳入完整自动化测试
- 已有能力：本地统计、速记、复盘、待办、备份、Agent API/MCP、写入快照和审查
- 改进分支：`improvement/ci-regression-coverage`

### 本次基线结果

- `npm ci`：通过，依赖安装完成；npm 审计报告 1 个 moderate 依赖问题，尚未升级依赖，避免混入无关变更。
- `npm run build`：通过。
- `npm test`：通过。
- 单元测试：37 项通过。
- MCP 冒烟：33 个工具可列出，握手、ping 和未知方法处理可验证。

### 已知缺口
- 未建立可重复的小型/大型 vault 性能基准，阶段 4 仍缺量化耗时与内存验收。
- 首次使用引导、草稿恢复状态、移动端草稿与附件完整验收仍需真实 Obsidian/移动端流程验证。
- MCP 冒烟未覆盖所有工具的参数校验、认证失败和 HTTP 错误返回。
- Agent 并发冲突、幂等重试、令牌轮换与审计脱敏仍需独立回归用例。
- 数据迁移已有未知版本保护，但大范围 schema migration 与损坏恢复需要真实 vault fixture。

## 原则与范围

1. 先稳固已有功能，再扩展新能力。
2. 用户数据不可静默丢失或覆盖；失败要可诊断、可恢复。
3. Agent 写入应有清晰权限、冲突检测、审计和回滚路径。
4. 优先增量计算与可测量优化，避免没有基准的性能改动。
5. 每个阶段拆成小 PR/提交，附测试与验收结果。

## 阶段 0：建立现状基线

### 工作项
- 运行并记录 `npm ci`、`npm run build`、`npm test` 的结果。
- 盘点现有单元测试、MCP 冒烟测试及尚未覆盖的高风险路径。
- 记录关键数据格式、迁移逻辑、统计口径、Agent 写入权限和恢复流程。
- 设计可重复的小型/大型 vault 测试样本，确定性能测量方法。

### 验收
- 明确当前基线通过/失败项目和可复现步骤。
- 形成测试缺口列表；性能指标有一致的输入和测量方式。

## 阶段 1：CI 与回归测试（首个实现阶段）

### 工作项
- 在 PR 和主分支 CI 中运行构建、单元测试和 MCP 冒烟测试。
- 检查 CI 使用的 Node 版本、依赖锁定和失败日志是否足够清楚。
- 覆盖日期边界、统计公式、数据规范化及已有数据迁移。
- 覆盖速记保存、待办状态、Agent 任务认领/完成、备份和恢复等核心行为。
- MCP 测试覆盖工具清单、参数校验、错误返回和启动/关闭流程。
- 确保测试不依赖开发者本机配置或真实个人 vault。

### 验收
- 每个 PR 都自动运行 build 与完整测试。
- 失败用例可定位到具体行为；测试可在 CI 稳定重复。
- 核心数据读写和高风险操作有自动化回归测试。

## 阶段 2：数据可靠性与统计可信度

### 工作项
- 明确数据格式版本、迁移顺序和未知版本处理策略。
- 损坏或不完整的数据文件在修复前保留原始快照，禁止静默覆盖。
- 验证创建、改名、删除、外部同步、重复文件事件对统计的影响。
- 明确人工编辑、粘贴、大段捕获、Agent 写入和系统文件的统计口径。
- 校验备份保留策略、备份损坏检测和恢复流程。
- 为异常统计提供诊断信息和可操作的修复路径。

### 验收
- 数据升级和失败恢复有自动化测试。
- 迁移失败时原始数据仍可找回。
- 文档描述与实际统计口径一致；重复事件不会造成明显重复计数。

## 阶段 3：Agent/MCP 安全与写入保护

### 工作项
- 测试服务仅监听回环地址；令牌缺失、错误或失效时拒绝请求。
- 测试路径遍历、黑名单/白名单、标签过滤及 `.obsidian`、`.git` 等边界。
- 验证读、新建、Patch、覆盖、删除等设置开关真实生效。
- 为可重试写入设计幂等行为，避免重复创建笔记、速记或任务。
- 对并发修改提供冲突检测与明确错误，不静默覆盖用户内容。
- 覆盖快照、Diff、恢复和审计日志；避免日志记录令牌或不必要的笔记全文。
- 按只读、沉淀、任务和维护整理 MCP 工具说明及风险提示。

### 验收
- 安全边界和权限开关都有自动化测试。
- 失败、冲突和重试有确定行为，用户内容可审查和恢复。
- 审计日志不泄露敏感凭证。

## 阶段 4：大 vault 性能与资源管理

### 工作项
- 检查文件监听是否触发重复全库扫描；优先增量更新和合理去抖。
- 测量搜索、语义索引、图谱查询、复盘计算和看板渲染耗时。
- 检查统计、速记、工作日志、工具调用记录及备份是否无界增长。
- 检查缓存失效规则、长任务反馈和内存峰值。
- 验证插件停用/重载后监听器、计时器和本地 API 正确清理。

### 验收
- 建立可重复的小型与大型 vault 性能基准。
- 常见文件修改避免不必要的全库计算。
- 数据保留策略明确；停用和重载不会残留重复监听或端口占用。

## 阶段 5：使用体验与移动端

### 工作项
- 改善首次使用引导，说明数据位置、统计口径、权限和备份。
- 提供精简/完整看板模式，降低初次打开的信息负担。
- 补齐空状态、加载状态、错误信息和权限提示。
- 以快速捕获为移动端首要流程，验证草稿恢复、标签、待办和小屏布局。
- 清楚标注桌面专属能力（例如 Agent API）及移动端限制。

### 验收
- 用户能理解如何开始、数据存在哪里以及如何恢复。
- 移动端核心速记流程可用，界面不依赖完整桌面看板。

## 阶段 6：检索、国际化与差异化

### 工作项
- 用中英文及混合语言样本评估 TF-IDF、分词和同义词扩展。
- 先优化分词、过滤词和结果解释；再评估可选本地 embedding，避免强制模型依赖。
- 补齐设置、Agent 安全说明、安装与故障排除的英文文档/界面。
- 为插件 API 明确版本和兼容策略，便于与其他插件集成。
- 聚焦三条价值主线：知识工作统计、快速捕获、可控 Agent 沉淀。

### 验收
- 检索有可重复测试语料和相关性评估。
- 中英文关键路径经过验证；对外 API 有版本说明。
- 新功能对应明确用户场景，不以工具数量作为目标。

## 阶段 7：发布与维护机制

### 工作项
- 建立发布清单：版本号、变更记录、构建、测试、安装升级和恢复验证。
- 维护兼容性说明、已知问题和升级/卸载/恢复指引。
- 优化问题模板，收集必要环境信息但不要求公开敏感笔记。
- 清楚说明本地数据边界、外部客户端依赖及 Agent 权限。
- 根据真实用户反馈调整优先级，控制维护成本。

### 验收
- 每个发布可追溯变更与验证结果。
- 用户能按文档升级、卸载并保留/恢复数据。

### 阶段 7 交付状态
- CI 与标签发布流程会执行构建、完整测试和发布文件校验。
- 发布校验覆盖 package / manifest / MCP bridge 版本一致性及变更记录存在性。
- 缺陷反馈模板要求脱敏环境信息，不要求公开笔记或令牌。
- README 增加升级、卸载、恢复和本地 Agent 权限说明。
