# Sediment 产品设计优化计划

> 本计划只讨论产品设计与体验优化，不包含商业化方案。目标是让 Sediment 从功能丰富的插件，收敛为一套清晰、可信、本地优先的个人知识工作与 Agent 协作流程。

## 产品目标

围绕一个完整闭环组织产品：

**捕获 → 今日行动 → Agent 协作 → 知识沉淀 → 周期回顾**

用户应能快速记录想法、知道接下来做什么、让 Agent 在明确权限内协助，并在之后找回和复盘成果。统计和可视化服务于这个闭环，不应成为用户必须先理解的主流程。

## 设计原则

1. **本地优先**：核心数据保存在用户的 vault 中，内容可读、可导出。
2. **渐进披露**：首次使用只呈现必要能力，高级分析和 Agent 配置按需开放。
3. **可解释**：统计、检索和自动化结果说明来源与计算口径。
4. **可审查、可恢复**：重要写入可预览差异、确认、撤回或恢复。
5. **一致的数据与权限**：看板、HTTP API 和 MCP 使用相同领域规则和权限边界。
6. **移动端场景优先**：手机重点支持捕获、任务和摘要，不缩小复制桌面仪表盘。
7. **减少概念负担**：用户不需要了解内部工具数量或数据结构才能完成日常工作。

## 信息架构

建议以三个主要入口组织功能：

| 入口 | 首要问题 | 功能范围 |
| --- | --- | --- |
| **今天** | 今天要做什么、记录什么？ | 今日目标、速记、任务、番茄钟、Agent 今日动态 |
| **知识** | 最近积累了什么、如何回顾？ | 热力图、统计分析、相关笔记、周复盘、年度画像 |
| **Agent** | Agent 正在做什么、改了什么？ | 连接状态、任务队列、知识草稿、变更 Diff、恢复 |

首次安装默认进入“今天”。热力图、年度画像、月报、分享卡和画风等保留为辅助功能，不与核心日常任务争夺首屏注意力。可提供精简视图与完整视图，避免第一次打开时信息过载。

## 整体 UI 优化

### 首屏与核心操作

看板顶部横幅约 200px，且把今日目标、连续天数、分享图、番茄钟、速记、任务和 Agent 动态同时展示在首屏。装饰和辅助信息可能压过核心操作。

- 缩短默认横幅高度，或提供低装饰/紧凑模式。
- 首屏突出“记一条速记”“开始/查看今日任务”“开始专注”。
- 连续天数、战报分享、画风切换等移到次级位置。
- 快速速记支持一次提交后继续保留或清空输入，并明确保存状态。
- 今日卡片只展示最关键指标，不与同类型内容重复。

### 知识页与复盘层级

知识页同时包含概览、热力图、趋势、目录分布、节律矩阵、年度画像和周复盘，容易变成长报表。

- 先展示本周摘要、值得回看的线索和下一步行动，再展开详细图表。
- 热力图、趋势、投入分布、年度画像按二级入口或折叠区组织。
- 数据分析和年度画像不默认占据首屏高度。
- 周复盘把结论、未完成事项、知识成果和下一步行动放在详细指标之前。
- 详细图表保留，可在需要时展开、切换或横向查看。

### Agent 页面

Agent 页面同时展示连接状态、变更审查、待办、双色热力图、草稿和工作日志；其中统计和待处理事项的优先级不同。

- 默认优先展示待审核草稿、待认领任务、最近变更和恢复入口。
- 连接状态与调用统计收进诊断区，不占用首屏主卡片。
- 人机热力图移动到知识分析页。
- 草稿卡片展示标题、来源、类别、修改摘要和明确操作。
- 最近变更先展示文件名、操作类型、时间、差异和恢复入口。

### 速记侧栏

右侧栏的“全部、回顾、漫步、标签、沉淀”五个页签与列表下的附加区叠加后，在窄屏中容易拥挤。

- 默认突出快速输入、搜索和最近速记。
- 回顾、漫步、标签和沉淀作为次级筛选或可折叠菜单。
- 手机端可横向滑动页签、使用“更多”菜单或底部操作区。
- 编辑、复制、分享、归档、删除和转 Agent 等操作统一为清楚的行内或操作菜单，不默认全部平铺。
- 草稿恢复、保存成功/失败和附件状态使用明显且一致的反馈。
- 当前笔记关联速记和工作日志放在独立区块，不挤占速记输入区。

### 状态反馈与数据可信度

- 修复或移除占位数据显示，例如知识概览中的固定“0 小时”；无法计算时明确显示“暂无数据”及原因。
- 异步卡片统一设计加载中、成功有内容、空状态和失败四种状态。
- 保存、归档、删除、合并、恢复等操作提供明确的目标和结果反馈。
- 删除、覆盖、批量合并等高影响操作应确认影响范围，并提供可恢复入口。
- 局部刷新优先于整页重绘，避免打断未提交输入、滚动位置和键盘焦点。

### 响应式与移动端

现有窄屏断点主要调整间距和字号，不足以处理多卡片滚动、导航拥挤和热力图横向溢出。

- 手机端优先保留速记、今日任务、快速委派和 Agent 摘要。
- 桌面端保留完整统计、年度画像、管理和审查能力。
- 热力图和宽表格在窄屏横向滚动或提供可折叠摘要。
- 日期、任务和操作按钮保持足够触达尺寸，不依赖悬停。
- 复杂图表不强制在移动端完整显示。
- 明确标注哪些能力仅桌面可用，不让用户误认为插件故障。

### 主题、字体与可访问性

- 核心界面继续使用 Obsidian 语义化主题变量，固定色仅用于插画和明确色彩编码。
- 顶部横幅与白色半透明导航按钮在深色、自定义主题和高对亮度主题下逐一验证。
- 棋盘、标签、状态、禁用状态和图例不能只靠颜色区分。
- 统计和图表提供文字摘要、数据标签或无交互替代说明。
- 所有按钮、页签、热力格子和操作菜单可由键盘访问并具有清晰焦点。
- 检查 Tab 顺序、对比度、触达尺寸、标签名称和缩放后的布局。

## 核心工作流

### 1. 捕获与速记

速记是低摩擦入口，建议让用户清楚看到每条记录下一步的处理状态：

- 未处理/未分类
- 转为笔记
- 委派给 Agent
- 已归档或纳入复盘

主要入口应包括快速新建、关联当前笔记、待处理速记和已沉淀成果。保存失败时保留输入；草稿恢复、删除恢复和附件处理应有明确状态。速记仍以普通 Markdown 为可读数据形式，离开插件也能访问。

### 2. 今日任务与行动

统一展示原生待办与 Agent 任务，并标注来源、状态和下一步操作：

- 本地待办：链接到原始笔记与行位置。
- Agent 待办：展示委派来源、认领状态和结果。
- 知识草稿：展示待审核、已采纳或已驳回状态。
- 已完成事项：保留结果链接和来源记录。

避免 UI、MCP 和速记模块各自维护互不一致的任务状态。任务完成或委派应有明确反馈，并可回到来源。

### 3. Agent 协作与安全写入

将 Agent 工作流呈现为可理解的协作过程：

**读取上下文 → 提出草稿/修改 → 展示差异 → 用户确认（按风险）→ 写入 → 保留来源与恢复点**

- 低风险、用户明确授权的操作可按配置自动执行。
- 覆盖、删除、批量修改等高风险操作应要求确认。
- 所有写入使用一致的权限检查、快照和冲突处理逻辑。
- 草稿可采纳、修改、合并、驳回或稍后处理。
- 变更审查需显示文件、修改范围、操作来源和恢复入口。

31 个 MCP 工具是集成能力，不必逐个映射到普通用户界面。界面按用户任务分组：上下文、检索、任务、知识沉淀、审查恢复和诊断。

### 4. 知识沉淀

Agent 生成内容应保留来源路径、相关任务或速记、创建时间和审核状态。用户应能选择：

- 创建独立知识笔记
- 合并到已有笔记
- 作为草稿保留
- 驳回或删除

合并前展示差异；采纳后仍能追溯原始工作记录。不要让 Agent 静默覆盖长期笔记。

### 5. 周期回顾

周复盘先帮助用户做决策，再呈现详细数据。建议顺序：

1. 本期值得回看的线索与已完成成果
2. 未完成事项和未处理速记
3. 有价值的新知识及来源
4. 与上期对比的简明指标
5. 下一步行动与归档
6. 可展开的详细图表和统计口径

复盘结论应可保存为普通 Markdown，并能关联到后续任务或知识笔记。

## 统计与检索体验

### 统计可信度

每个指标应提供简明说明：计算口径、统计范围、数据来源、排除规则和可能的估算误差。区分人工编辑、粘贴、大段捕获、Agent 写入和系统文件等来源；允许用户检查统计范围和修正明显异常。贡献分作为辅助指标，不应被描述成知识质量的权威衡量。

### 统一搜索入口

统一搜索笔记、标签、速记、工作日志、知识草稿和当前笔记关联内容。结果应标出：

- 匹配类型与来源
- 匹配原因（标题、正文、标签、相关词等）
- 所在目录和更新时间
- 相关性属于精确匹配还是语义推测

中文、英文及混合语言检索分别验证。可先改进本地分词、同义词和结果解释，再评估可选本地 embedding；避免把大型模型作为基本功能的强制依赖。

## 数据与技术边界

建议形成统一领域模型与服务，避免 UI、HTTP、MCP 分别实现业务规则：

- `DayStats`
- `Memo`
- `Task`
- `WorkLog`
- `KnowledgeDraft`
- `AgentChange`
- `BackupSnapshot`

关键对象应有稳定 ID、时间戳、状态、来源和必要的关联标识。数据层需支持 Schema 版本、迁移、完整性校验、备份恢复和导出。统计、搜索和图谱尽可能通过文件变更增量更新；缓存有明确失效规则。

概念架构：

```text
Obsidian 文件事件
        ↓
数据规范化与增量索引
        ↓
统计服务 | 速记与任务服务 | 检索与图谱服务 | Agent 权限/写入服务
        ↓
看板 | HTTP API | MCP | 备份与导出
```

所有入口共享领域服务、权限检查和错误处理。停用或重载插件时正确清理监听器、计时器和本地 API。

## 权限与设置体验

将设置从分散的复选框收敛为容易理解的工作模式，并显示各模式的实际影响：

- **只读**：Agent 可检索和读取允许范围内的内容。
- **草稿**：Agent 可生成草稿，不直接改动已有笔记。
- **确认后写入**：每次实际写入前预览并确认。
- **自动执行**：仅对用户明确允许的范围自动执行，高风险动作仍可单独限制。

详细设置仍可保留供高级用户使用。设置页说明目录范围、标签限制、创建/Patch/覆盖/删除能力、快照与审计行为。避免用户面对一组开关却无法判断组合效果。

## 移动端体验

移动端作为快速工作流设计，而不是压缩版桌面看板：

- 一键速记和草稿恢复
- 图片/附件捕获及保存状态
- 今日任务与 Agent 任务摘要
- 快速委派待办
- 查看草稿摘要、最近变更和复盘摘要
- 离线草稿、同步状态和失败重试

复杂分析、年度画像和管理设置可以放在桌面端。明确标注桌面专属能力（如本地 Agent API），避免用户误认为功能故障。

## 新手引导与状态反馈

首次使用引导优先完成少量必要配置：

1. 选择日记目录和日期格式。
2. 确认统计范围与排除目录。
3. 了解数据存储位置及备份方式。
4. Agent 接入作为可选步骤，解释访问权限和本地网络边界。

完善加载中、空状态、保存成功/失败、权限拒绝、冲突、恢复成功/失败等反馈。关键错误应包含下一步建议，但避免在日志或错误提示中泄露令牌或笔记内容。

## 分阶段实施

### 第一阶段：信息架构与用户路径

- 绘制“今天—知识—Agent”导航原型。
- 确定首屏只显示的核心信息和次级功能入口。
- 梳理速记到任务、草稿、知识和复盘的状态流转。
- 定义关键空状态与错误状态。
- 缩短或提供紧凑模式的顶部横幅。
- 确定知识页的摘要与详细图表折叠规则。
- 调整 Agent 页，优先展示待处理事项。

**验收：**新用户能从首屏完成速记、查看任务、找到周复盘；主要功能入口和状态含义清楚；知识页和 Agent 页不再把装饰或诊断信息放在核心任务之前。

### 第二阶段：Agent 审查闭环

- 统一权限检查与写入服务。
- 设计草稿、差异预览、确认、冲突和恢复体验。
- 高风险写操作提供确认与快照。
- 统一看板、HTTP、MCP 的行为。
- 为 Agent 草稿卡片、最近变更和工作日志统一操作反馈。

**验收：**每次重要修改都能说明来源和影响；用户可审查并恢复；拒绝或冲突时不静默丢失内容。

### 第三阶段：任务、速记和复盘状态统一

- 统一任务来源、状态和结果关联。
- 明确速记处理状态与转化去向。
- 将周复盘组织为“线索—行动—归档”流程。
- 简化速记侧栏输入、搜索和最近记录的视觉优先级。
- 将回顾、漫步、标签、沉淀改为次级入口或筛选器。
- 确认行内操作、操作菜单与快捷键的统一。

**验收：**用户能从速记/待办追踪到 Agent 结果或知识成果；状态变化在各入口一致；窄侧栏能完成主要速记操作而不被附加区挤占。

### 第四阶段：数据可信、统一检索与状态反馈

- 显示统计口径、来源和排除范围。
- 统一搜索入口及结果说明。
- 加入数据迁移、备份恢复和异常修复的用户反馈。
- 修正固定占位或错误的统计展示，无法计算时显示“暂无数据”。
- 为异步卡片统一加载、成功、空数据和失败状态。
- 优先局部刷新，保留滚动、焦点、草稿和未提交输入。

**验收：**统计和检索结果可解释；数据升级和恢复流程有明确反馈；异步操作不会静默失败或覆盖未提交内容。

### 第五阶段：移动端与渐进式设置

- 优先打磨移动端捕获、任务和摘要。
- 设计权限工作模式和首次使用引导。
- 根据使用反馈调整精简/完整看板。
- 针对 500px 以下和窄侧栏验证布局与触达尺寸。
- 让宽表格、热力图和复杂图表在窄屏横向滚动或折叠。
- 在浅色、深色和自定义主题下验证对比度与焦点状态。

**验收：**手机端核心捕获流程顺畅；新用户能理解数据位置、权限与 Agent 的可选性；主要功能可由键盘和触屏完成，主题切换不造成不可读元素。

## 设计验证指标

不以功能数量衡量完成度，观察用户是否能顺利完成任务：

- 首次安装后完成基本设置所需步骤与时间
- 从打开插件到记录一条速记所需操作数
- 用户能否找到未处理速记和今日任务
- 用户能否解释关键统计指标的含义
- Agent 修改是否能被正确预览、确认或恢复
- 周复盘是否能形成可追踪的下一步行动
- 手机端捕获失败率和草稿恢复成功率
- 知识页完成一次有针对性的回顾所需时间
- Agent 页完成草稿审核或变更恢复所需操作数
- 深色主题、窄屏和键盘导航下的可读性与可操作性

通过可用性测试和真实反馈验证，不把这些指标用于上传用户笔记内容或个人工作轨迹。

## 建议优先级

1. 收敛首页与导航，突出“今天—知识—Agent”。
2. 修正错误占位数据并统一异步状态和操作反馈。
3. 简化知识页、Agent 页和速记侧栏的信息层级。
4. 统一任务和速记状态模型。
5. 把 Agent 写入做成一致的预览、确认和恢复流程。
6. 提升统计口径和检索结果的可解释性。
7. 简化首次设置与权限模式。
8. 完成移动端、主题和可访问性验证。
9. 在核心流程验证后再扩展视觉、分享和分析功能。
